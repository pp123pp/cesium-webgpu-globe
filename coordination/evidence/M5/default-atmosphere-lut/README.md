# 默认大气 LUT 首帧 A/B

2026-11-06，本机 Intel Xe-LPG，Chromium 156.0.8078.4，640×360。A 用生产 CPU 模型生成两张 LUT，B 对默认 WGS84 介质使用内嵌的半浮点表。两者共用以 `43e6e6f` 为基础的同一份云、地形和影像工作树。测试直接创建 WebGPU Viewer，固定 UTC 2026-03-20 12:00、赤道 30 km 水平视角，绘制天空并隐藏地形，以隔离大气首次出现的成本。

按 A/B/B/A、A/B/B/A 启动 8 个独立浏览器。每个浏览器以两个新页面分别测冷、暖 HTTP 缓存，均新建 Viewer、device 和 LUT。冷页面实收 gzip 脚本，暖页面的脚本传输量为零。系统和驱动缓存沿用当前机器状态。每个版本和缓存组合各有 4 个样本，表中均为中位数。首帧必须提交恰好一次大气合成和一次 LUT 初始化。计时终点为 GPU 队列完成，屏幕呈现时间未测。

| 毫秒 | 冷 A → B | 暖 A → B |
| --- | ---: | ---: |
| 导航至脚本可执行、即将创建 Viewer | 522.3 → 558.0 | 480.3 → 515.3 |
| 首帧大气 update 同步 CPU | 121.7 → 2.1 | 127.1 → 2.6 |

大气 update 的计时包含生成或解码、提交纹理上传和该方法的常规初始化。两版首帧 CPU 样本范围完全分开。整页从导航至首帧的冷缓存范围为 A 2180.7–2426.1 ms、B 2302.9–2458.7 ms，暖缓存为 A 2079.2–2307.1 ms、B 2174.9–2440.1 ms。整页中位数分别改善 9.7 和 45.1 ms，但单次波动大于该差值。未压缩脚本增加 185,888 B，回环服务的 gzip 从 3,050,712 增至 3,117,317 B（+66,605 B）。其他网络条件下端到端收益仍待测。[逐页计时、资源传输量、bundle 哈希和 GPU 身份](samples.json)

## 默认 → 自定义 → 默认

定向模型测试通过 renderer 的上传入口核对两张表的全部 139,264 字节。首次默认和恢复默认都与原动态模型的半浮点结果逐字节一致。取海拔 1,000 m、天顶角余弦 0.2，恢复后的透射 RGB 为 `[0.8150609635, 0.6246820789, 0.3195418148]`，与首次默认一致。自定义介质和非默认行星均命中动态路径。[模型和上传回归测试](../../../ci/m2-atmosphere-model.test.mjs)

两版均在首帧计时完成后独立捕获实际 canvas 像素。Rayleigh 标高 8,000 → 12,000 → 8,000 m，B 的预烘加载次数为 1 → 1 → 2。默认图像包含 723 个采样颜色，RGBA 哈希为 `e9075dbcac1462797f189a000d77e201071b661af525756728ac310f7e1841ab`；切至自定义后为 `be9ff3627f93774d88713cb448c0f5606668203c06553297eeab8d29cb09076d`。两版的三个对应画面完全相同，恢复时重现初始像素。

## 复测

1. 在两份相同的候选工作区中构建 A 和 B。在 A 副本中应用本目录的 [基线补丁](baseline.patch)，恢复原始 renderer 的动态 LUT 路径。A 副本的 `packages/engine/Source/Scene` 还应排除新增的 `WebGPUAtmosphereHalf.js` 和 `WebGPUDefaultAtmosphereLuts.js`，因为构建会自动将该目录的模块导出到 bundle。B 保留这两个文件和预烘路径。分别执行 `npm run build`。
2. 将两份 `Build/CesiumUnminified/Cesium.js` 分别放入同一工作区的 `Build/default-lut-performance/A/Cesium.js` 和 `Build/default-lut-performance/B/Cesium.js`。从已构建的工作区运行 `node coordination/ci/m5-default-lut-profile.mjs`。夹具按仓库配置启动有界物理 GPU 浏览器，拒绝软件适配器，并在 `Build/default-lut-performance/samples.json` 保存原始结果。
