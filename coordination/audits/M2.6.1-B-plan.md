# M2.6.1-B — Implementation Plan and Visual Acceptance

Planning baseline: M2.6.1-A audit of main 045b30ff053f44c9be52e2ef504e86d416bd37ff.
This document is a plan only. It does not authorize implementation. Start B only after a separate explicit instruction.

## Principles and entry gate

- Preserve M2.6 A07–A10 acceptance and all physical invariants: scene-time Sun direction, angular radius, irradiance, WGS84 intersection, completed scene depth, real terrain occlusion and atmospheric transport.
- Preserve the linear RGBA16Float composition → Bloom → one ACES tone map → one sRGB encode path. No duplicate gamma/tone mapping.
- No lens ghosts, lens dirt, anamorphic streaks, exaggerated flare, volumetric clouds, automatic exposure, WebGL changes or general RenderGraph/PBR work.
- Work from a fresh main HEAD and inspect current files before editing. Use the existing M2.6 GPU capture harness and extend it only where a missing acceptance observation requires it.
- Prefer authored asset improvements and bounded changes to existing shader controls. Do not add a new render pass unless a capture demonstrates that existing composition cannot meet the visual target.
- Keep existing fallback, cancellation, device-loss, resize, resource accounting and idempotent lifecycle behavior.
- If a current effect already passes visual review, record it as retained/no-op rather than changing it to satisfy a task label.

## B01 — Solar Disc Polish

**Purpose:** improve disk/core transition without changing physical angular size or irradiance.
- Likely files: WebGPUSunShader.js; WebGPUSun.js only if a validated parameter is needed; focused shader/unit/browser fixtures.
- Plan: compare current analytic uniform disk against same-state captures. If flat-patch appearance is confirmed, add a restrained radial/limb profile in scene-linear radiance with pixel-footprint antialiasing. Keep angular radius, disk coverage, Earth/depth tests and irradiance normalization authoritative.
- Resources: no new texture by default; reuse authored gradient only if its role is explicitly justified.
- Depends on baseline capture and current exposure behavior.
- Tests: disk edge, partial/hidden disk, exposure 0.5/1/2, high-orbit and low-Sun.
- Done: near-white readable core, restrained warm edge, no abrupt cutout, no excessive clipping/saturation, unchanged angular footprint and occlusion.

## B02 — Sun Rays Polish

**Purpose:** remove decorative regular starburst appearance.
- Likely files: WebGPUSunShader.js; existing Solar/Rays SVG sources and generated GPU payloads only if artwork revision is justified; builder/manifest/tests if payloads change.
- Plan: inspect each existing mask and same-state isolated capture. Current masks share one UV transform and are weighted 0.48/0.30/0.22. First test deterministic small angular phase/scale variation per layer. Do not use frame-random noise or camera-local offsets. Preserve projection anchoring to actual Sun direction.
- Resources: reuse three masks first. Add or replace a mask only if existing artwork cannot provide distinct scales.
- Depends on B01 disk/core radius decision.
- Tests: effect isolation, high/low orbit, off-axis Sun, two viewport sizes, 120-frame motion.
- Done: non-uniform but restrained rays, no obvious aligned spokes/dots, moiré, hard cutoff, flicker or camera drift.

## B03 — Solar Halo Polish

**Purpose:** coherent inner, intermediate and outer falloff.
- Likely files: WebGPUSunShader.js and existing Solar/Halo assets; manifest/builder only if source assets change.
- Plan: assess current soft/wide maps. Tune relative contribution and radial extent before adding assets. Establish compact inner glow, soft intermediate halo and broad low-intensity outer falloff without a perfect ring or circular boundary.
- Resources: current two halo masks are preferred; third map only with demonstrated gap.
- Depends on B01/B02 final radial domain.
- Tests: exposure matrix, Bloom on/off, black-space contrast, off-axis and resized captures.
- Done: smooth transitions without ring, banding, rectangular/texture edge or washed-out stars.

## B04 — Solar Corona Polish

**Purpose:** restrained irregular multi-scale corona.
- Likely files: WebGPUSunShader.js; Solar/Corona and Solar/Noise sources; generated payload/manifest/builder if new artwork is necessary.
- Plan: current shader samples one fine corona mask and one noise map. Assess source artwork and capture. If detail is insufficient, add a broad or medium-frequency authored component and blend it at a different scale/weight. Keep it a visual representation, never claim magnetic-field or plasma simulation.
- Resources: reuse existing noise and fine map first; additional map adds 262144 bytes at current R8 512² format.
- Depends on B02/B03 coordinate/radius design.
- Tests: same-state isolation, high/low orbit, exposure, viewport and 120-frame stability.
- Done: recognizable irregular, restrained detail; no noisy particle cloud, repeated texture, disk occlusion or hard ring.

## B05 — Atmospheric Glow Integration

**Purpose:** ensure visual artwork integrates with physical atmosphere instead of replacing or double-counting it.
- Likely files: WebGPUAtmosphereShader.js and WebGPUSunShader.js only if evidence requires a correction; existing atmosphere and solar fixtures.
- Plan: compare atmosphere enabled/disabled at orbital limb, low-Sun horizon and ground-facing views. Separate physical scattering/attenuation from solar artwork and Bloom contributions. No second atmospheric glow layer unless physically/visually justified.
- Resources: no new texture by default.
- Depends on B01–B04 visual balance.
- Tests: atmosphere on/off diagnostics, sunrise, twilight, ground day/terminator/night, Earth and terrain occlusion.
- Done: smooth limb/terminator transition, no duplicate haze, solar artwork attenuated appropriately, no glow through Earth/terrain.

## B06 — HDR Bloom Refinement

**Purpose:** improve smooth HDR highlight spread while preserving black-space and disk detail.
- Likely files: WebGPUSolarBloomShader.js and WebGPUAtmosphereRenderer.js; targeted Bloom fixtures.
- Plan: tune existing linear threshold (currently 1.0), quarter-resolution extraction and diagonal blur radius/strength. Test whether current single blur scale is sufficient before considering multi-scale. Preserve post-blur depth/Earth receiver mask.
- Resources: reuse existing RGBA16Float linear/A/B targets. Any extra target or pass requires a measured visual need and explicit memory/pass budget.
- Depends on stable source radiance from B01–B05.
- Tests: Bloom enabled/disabled, exposure 0.5/1/2, 1920×1080 and 1280×720, Earth/terrain occlusion.
- Done: no square/low-resolution boundary, halo haze, star washout, disk-edge loss, receiver leakage, duplicate tone map or gamma error.

## B07 — Visual Integration

**Purpose:** integrate retained/changed effects and prove no functional, visual or lifecycle regression.
- Likely files: coordination/ci/m2.6.1 visual harness and evidence under coordination/evidence/M2.6.1; production files only where a preceding B task justifies them.
- Tests: fixed-camera captures, per-effect isolation, 120-frame progression, resize, exposure matrix, full/partial/hidden Earth and real terrain occultation, resource lifecycle, same-adapter GPU timestamps.
- Performance: compare against M2.6 closeout on the same adapter/resolution/scene. M2.6 reference all-enabled mean 16.80 ms, p95 20.45 ms; effects-on/Bloom-off mean 16.53 ms, p95 20.51 ms. These are historical comparison points, not guaranteed targets. Report actual mean/p95 and limitations; do not invent results.
- Done: all SVP-01–SVP-10 evidence complete; A07–A10 behavior preserved; no WebGL regression; targeted tests/lint/types/build pass; current required Fast/Full and separately authorized WebGL differential gates pass on final PR HEAD; resource counts balance.

## Dependencies and recommended order

B01 → B02 → B03 → B04 → B05 → B06 → B07.
B01–B04 may be implemented in small isolated batches only if shader ownership remains single-owner. B05/B06 depend on the settled source-radiance balance. B07 is the integration gate. Do not implement all tasks if capture review shows a component already meets its goal.

## Acceptance assertions

1. Solar disk is not a flat pure-color sticker; core/edge transition is controlled.
2. Rays are not mechanically repeated, dotted or hard-cut and remain anchored to true projected Sun position.
3. Corona has discernible irregular multi-scale detail without implying physical plasma simulation.
4. Inner/intermediate/outer halo falloff is smooth and has no obvious ring or texture boundary.
5. Sun and atmospheric limb glow form a coherent system without double-counting atmosphere.
6. No alpha black/white fringe, rectangular asset edge, banding or color-space artifact.
7. No incorrect gamma or duplicate ACES/sRGB conversion.
8. No solar artwork or Bloom leaks through Earth or real terrain.
9. Exposure changes preserve useful hierarchy; exposure 2 tradeoffs are documented, not hidden.
10. No physical correctness loss, temporal popping, resource leak or material unexplained performance regression.
11. Browser/GPU differences need not be pixel-identical; compare matched camera, time, exposure, viewport and provider state.
