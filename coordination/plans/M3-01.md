# M3-01 implementation plan

Goal: implement only the curved global cloud geometry and visible ray intervals
from task 1 of `tasks/M3.md`, then publish the development branch for user acceptance.

## Decisions

- Preserve ECEF meters and WGS84 flattening. Expand each ellipsoid axis by
  cloud altitude (default base 2000 m, top 6000 m). This is an approximation to
  constant geodetic altitude; quantify its error using native cartographic conversion.
  A maximum-radius sphere would introduce a 21.4 km polar discrepancy. Exact
  constant-height surfaces require iterative intersection and are unnecessary here.
- Keep private CPU layer parameters/intersection and binding-free WGSL in dedicated
  WebGPU files. Reuse planet state, native CPU intersection, ray reconstruction and
  native reversed depth. No changes to WebGL or normal scene rendering.
- Return up to two ordered shell intervals, including zero-length outer tangency;
  clip solid Earth and measured terrain before exposing visible segments.
- Render a deterministic geometry diagnostic with the same production WGSL against
  actual native mesh depth. Colors describe entry/exit/path length, not cloud density.
  No coverage, noise, scattering, LOD, temporal history, shadows or A11–A13 claims.
