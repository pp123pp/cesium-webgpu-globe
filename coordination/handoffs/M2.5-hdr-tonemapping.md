# M2.5 HDR, Exposure and Tone Mapping — Development Handoff

## Scope and baseline

- Base: `main` at `8693c44d721fa327c9765ffa74a8b21e8d09912d`
- Branch: `feat/m2.5-hdr-tonemapping`
- Scope: M2.5 only. M2.6 and M3 were not started.
- Existing M0–M2.4 implementation was retained; no WebGL Scene or WebGL shader path was changed.

## Implemented

- WebGPU globe color attachment now uses `rgba16float` for scene-referred intermediate color.
- Terrain base color and imagery texels are decoded from sRGB to linear RGB before opaque/alpha composition.
- The M2 atmosphere composite reads the linear HDR scene attachment and adds atmosphere, Sun, Moon, stars and moonlight without an intermediate sRGB encode/decode.
- Final display conversion is centralized in the existing atmosphere composite pass: manual exposure, fitted ACES curve, then sRGB encoding to the preferred canvas format.
- The final composite pass remains active when all celestial effects are hidden, so the HDR scene is always converted to display-referred output.
- `viewer.scene.exposure` defaults to 1.0 and validates finite values in [0.01, 16.0] on initialization and frame update.
- Default Sun disk radiance is now scene-linear HDR (>1.0) rather than pre-scaled for LDR output.
- HDR intermediate texture participates in existing resize and device release paths; it is destroyed alongside scene depth/color attachments.
- The M2 space browser smoke suite now measures actual rendered output at exposure 0.5, 1.0 and 2.0.
- Unit coverage added for exposure validation, sRGB transfer round-trip, ACES black/mid-gray/white/highlight behavior, and HDR solar radiance.

## Architecture decisions

- ACES fitted (Narkowicz) was selected for compact per-channel high-highlight compression and low ALU cost. It is applied once at final output.
- `rgba16float` is used as the minimal HDR target; no general RenderGraph or additional full-screen pass was introduced.
- HDR composition stays isolated to the WebGPU backend. The M0 proof's direct canvas path remains unchanged.
- No automatic exposure, bloom, or generic PBR/material system was introduced.

## Known limitations / risks

- The original software-browser attempt could not acquire an adapter; subsequent headed hardware acceptance is now recorded above. Physical performance and multi-device coverage remain unverified.
- WebGL was not changed; a WebGL differential suite was not run locally and is not claimed as verified.
- The HDR intermediate increases color attachment bandwidth relative to the previous canvas-format intermediate. It is one full-resolution `rgba16float` texture, not a multi-buffer graph.
- Exposure is a WebGPU Scene runtime property; no automatic exposure or UI slider was added.
