# M1.2 imagery state adapter

**Goal / ownership:** adapt actual provider imagery requests and native layer/cache/fallback lifetimes to WebGPU. Only `packages/engine/Source/Scene/WebGPUImagery.js`, `coordination/ci/m1-imagery-lifecycle.test.mjs`, and this handoff changed. Base `30692fd`; branch `feat/m1-imagery-state`. Root owns integration and acceptance.

**Behavior:** reuse native `ImageryLayer._createTileImagerySkeletons`, `TileImagery.processStateMachine`, cache references and ancestor fallback. Decorate only owned `Imagery` instances; leave all native prototypes unchanged. Handle scheduling deferral, cancellation, `TileProviderError` retries, tile credits, discard readiness, shared uploads, placeholder transitions, and layer ordering. Reuse skeletons that native layer/ready handlers created during terrain loading. At final release, cancel requests, close decoded images, destroy the wrapper once, and remove the owned record before native cache/ancestor cleanup. Late success closes its image; late failure cannot emit another provider error or upload.

**Interface:** `new WebGPUImagery(tileProvider, renderer)`, `updateTile(tile, frameState) -> boolean` (all imagery finished), `destroy()`, and `statistics` containing `requests`, `deferred`, `failed`, `discarded`, `imagesClosed`, `pendingRequests`, `texturesCreated`, `texturesDestroyed`, `activeTextures`. `renderer.createImageryTexture(image)` synchronously copies/uploads and returns `{ texture, view, width, height, destroy() }`; the adapter closes the image afterward.

**Projection / integration:** `imagery.texture` and `.textureWebMercator` share one native-projection wrapper. Keep native coverage coordinates; derive sampling from the provider projection, including polar Mercator associations with `useWebMercatorT === false`. The renderer adds `imagery.credits` and provider credit on every drawn frame. The provider must preserve native combined terrain/imagery `upsampledFromParent` semantics; independently ready imagery can justify finer LOD over upsampled terrain.

Fresh worktree setup required generated shader imports and `npm run build-ts --workspace @cesium/core`; declaration generation completed with inherited JSDoc warnings. Existing dependencies were reused; no tracked dependency changes.
