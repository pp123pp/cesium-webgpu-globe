# M1.1 GPU Globe handoff

**Result:** real WGS84 ellipsoid meshes, native Camera/Globe/Quadtree and WebGPU rendering pass the foundation browser gate. This is A03 foundation evidence, not M1 completion: imagery and quantized-terrain rendering follow in the next slices.

**Files:** new `WebGPUScene.js`, `WebGPUGlobeRenderer.js`; narrow integration in `WebGPUContext`, `WebGPUWidget` and `Viewer`; `m1-globe-smoke.mjs` and `m1-renderer-lifecycle.test.mjs`. The original `Scene`, `Globe`, WebGL `Context` and native tile algorithms are unchanged. `globe:false` explicitly retains the M0 proof/demo.

## Behavior

- Viewer exposes native Camera, Globe, ImageryLayerCollection, terrain provider, Clock and credits through an isolated SCENE3D coordinator. Native screen-space controls, camera changes, quadtree selection, terrain workers, horizon tests and CPU terrain picking are reused. No WebGL context is created.
- Upload actual native terrain meshes and skirts using RTC coordinates; form the reversed-depth projection in CPU double precision and use `depth32float`, greater comparison and zero clear. Per-draw uniforms have aligned independent offsets. Respect back-face culling, underground viewing and skirt selection.
- Destroy mesh/uniform buffers, pending terrain work, input listeners and owned DOM. Provider replacement retires old work immediately; late completions cannot affect the new provider. Direct Scene errors (including clock failures) use the Scene as event source and respect `rethrowRenderErrors`. Explicit weak ownership prevents a second Viewer from adopting a Globe before its first frame.
- Unsupported scene modes, terrain exaggeration, materials, clipping and translucency raise explicit errors. Atmosphere, Sun, clouds, 3D Tiles and other M2+ rendering are absent.
