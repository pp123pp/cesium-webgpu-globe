## What changed

- `WebGPUAtmosphereModel.js`: original meter-based CPU optical model, validated
  mutable settings, 256×64 transmittance and 32×32 reduced Hillaire multiple
  scattering LUTs; focused physical tests in `m2-atmosphere-model.test.mjs`.
- `WebGPUAtmosphereShader.js`: consumes the unchanged 192-byte M2.1 planet
  contract; 32 intervals clustered near minimum height integrate visible
  atmospheric radiance/transmittance. Actual WGS84 shadow, real depth and Earth
  boundaries clip rays. The output is decoded scene color times RGB
  transmittance plus linear in-scattering, encoded for the current LDR target.
- `WebGPUAtmosphereRenderer.js`: two RGBA16Float LUT textures, two uniform
  buffers, one fullscreen pipeline; medium-key caching and resize rebinding.
  `WebGPUContext.js` owns a separate completed-color attachment and ends the
  opaque pass before sampling it and depth in the composite.
- `WebGPUScene.js` / `WebGPUGlobeRenderer.js`: enabled-default
  `scene.atmosphere`, update/composite/lifetime integration. M1 terrain RTC,
  depth ordering, imagery, navigation and native WebGL source remain unchanged.
- `m2-atmosphere-fixtures.mjs` / `m2-atmosphere-smoke.mjs`: execute production
  WGSL, actual LUT/depth readbacks and canvas pixels with real native resource
  instrumentation. `m2-atmosphere-lifecycle.test.mjs` covers completed-pass
  routing, disabled rendering, resize and allocation/submission failure cleanup.
- `m1-browser-harness.mjs` and `m1-globe-smoke.mjs`: M1 geometry/provider/navigation
  fixtures disable atmosphere to preserve their original assertions. The public
  demo retains its enabled default. `m1-navigation-smoke.mjs` counts both
  terrain and atmosphere buffer owners in its strict native-allocation equality.
- Both Fast/Full workflows require the new atmosphere browser gate and upload
  `Build/m2-atmosphere/`. Existing gates, assertions and Full policy stay intact.

## Diagnosed failures and approximations

- Initial model-index build failure was a new integration issue: Cesium's
  automatic source index requires a default export. Added the model namespace
  default; build and actual browser loading then passed.
- The initial new oblique-mountain assertion failed by 2.00364 m over 41.321 km.
  Native picks using the GPU ray differed by only 1.55 mm. Measured local depth
  slope made the discrepancy approximately 0.015 pixel. Chromium SwiftShader's
  documented legacy configuration has a 1/16-pixel raster grid. The new fixture
  now measures four fixed ±1/16-pixel corner picks, requires valid terrain and a
  span below 25 m, and retains the 1 cm + 2 ppm numerical allowance. M2.1's
  existing strict assertions are unchanged. Actual on/off GPU terrain depth
  must be bit-identical; off-axis, real-depth interval and ellipsoid-only controls
  remain mandatory. See the primary links and scope in the model contract.
- Low-orbit diagonal NaturalEarth color seams are visible with atmosphere
  disabled at the identical camera and are inherited M1 imagery appearance.
  Both captures are retained. This task neither creates nor declares them fixed.
- Radial WGS84 density height is zero on the real ellipsoid; LUT curvature uses
  its equatorial reference sphere. Medium density ends at 100 km radial height;
  the enclosing M2.1 sphere remains 121.384686 km above the pole. This is not an
  exact ellipsoidal optical solver or a claim of uniform radiance error.
- Reduced isotropic multiple scattering uses black ground, 32 angular samples,
  64 path intervals and `J1/(1-min(f,0.95))`; default raw maximum feedback is
  0.33370227. No ground bounce, ozone, spectral conversion or terrain-cast solar
  shadow volumes. The real ellipsoid supplies planetary solar occlusion.
- M1's unlit surface appearance remains visible on the night side. Atmospheric
  direct sunlight is occluded; no new surface BRDF or lighting model is claimed.
  Current output remains LDR and can clip bright Mie highlights. Full HDR,
  photometric exposure/tone mapping and bloom remain M2.5.
- Local sandbox denied browser/socket creation; the authorized native-process
  execution ran the same tests successfully. These are environment restrictions,
  not ignored renderer failures. No important test was removed or disabled.
- **M1-NAV-001 remains KNOWN_UNRESOLVED** and Google ion's rejected endpoint
  cache/retry limitation remains. Their old failures are not M2.2 passes.
