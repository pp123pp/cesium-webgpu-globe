# M1.4 center-wheel roundoff fix

**Problem:** the real native wheel controller intermittently throws `normalized result is not a number`. A deterministic browser case at 45°E, 45°N and 12,000,000 m, pointer exactly (640, 360), produces normalized self-dot `0.9999999999999998`, a zero cross-product axis and angle `5.880415029710569e-9`. Native `Camera.rotate` then attempts to normalize the zero axis. Earlier intermittent passing wheel runs do not disprove this case.

**Change:** only while the WebGPU coordinator invokes native controller `update()`, treat an exactly zero axis with a finite angle smaller than `1e-7` radians as a no-op. Forward all other rotations unchanged and restore the original method/property ownership in `finally`. Native Camera/controller source and WebGL behavior remain unchanged; invalid direct public rotations still throw.

**Files:** `WebGPUScene.js`, `m1-controller-roundoff.test.mjs` and this note. Root owns integration; the navigation agent owns the independent browser regression.

**Executed checks:** two focused roundoff/exception-restoration tests and six renderer/lifecycle tests pass; targeted ESLint/Prettier and engine TypeScript pass. The independent actual browser regression retains the deterministic RED with exact axis/angle and native stack. Its GREEN rerun and final navigation acceptance are pending at this commit, not claimed here.
