## API and example

```js
const viewer = new Cesium.Viewer("cesiumContainer", {
  renderingBackend: "webgpu", // default remains "webgl"
  useDefaultRenderLoop: false,
});
viewer.renderError.addEventListener((source, error) => console.error(error));
await viewer.readyPromise;
viewer.resize();
viewer.render();
// When the application removes this Viewer:
viewer.destroy();
```

The WebGPU subset is `container`, `canvas`, `renderingBackend`, `readyPromise`, `renderError`, `useDefaultRenderLoop`, `resolutionScale`, `useBrowserRecommendedResolution`, `resize`, `forceResize`, `render`, `destroy`, `isDestroyed`. `scene` and other unsupported APIs throw; no fake Cesium Scene is exposed. Non-3D modes and explicit unsupported feature options are rejected. Backend cannot be changed on a live Viewer. Startup cancellation rejects readiness without a late resource leak; recreating a Viewer is the recovery path after device loss.

### CI environment diagnosis

Runs [41390520001](https://github.com/pp123pp/cesium-webgpu-globe/actions/runs/41390520001) and [41391014154](https://github.com/pp123pp/cesium-webgpu-globe/actions/runs/41391014154) failed creating the WebGPU canvas shared image (`SharedImageBackingFactory`); switching only from headless shell to full Chromium did not resolve it. Enabling the software Vulkan sharing path produced passing GPU checks in run 41391388057, without further product-source changes.

Headless screenshots were entirely transparent in runs 41391388057 and 41391868042, even after two animation frames and a GPU queue fence. With the same GPU parameters, headed Chromium under Xvfb produced the verified visible screenshots in run 41392263849. This records the tested environment difference, not a claim that every Linux headless configuration fails.

The test uses headed Chromium under Xvfb with `--enable-features=Vulkan,VulkanFromANGLE`, `--use-angle=swiftshader`, `--use-vulkan=swiftshader`, `--use-webgpu-adapter=swiftshader`, `--disable-vulkan-surface`, and explicit WebGPU/SwiftShader opt-ins. This follows [Chromium WebGPU pixel-test software configuration](https://chromium.googlesource.com/chromium/src/+/master/content/test/gpu/gpu_tests/pixel_test_pages.py) and the [Linux VulkanFromANGLE requirement](https://chromium.googlesource.com/chromium/src/third_party/+/5a2251013650018561456d5e882c92f4b541bac7). These are CI browser settings, not application runtime requirements or physical-GPU performance evidence.
