# M0.3 source pipeline audit

Date: 2026-11-02
Scope: read-only audit of CesiumJS 1.146.0 source; no engine/widget/renderer files modified.
Source commit: `b8d3a36fe98a3e432eb89253c95d5f20e605e0f1`.

## Verified call path

1. Public entry: `packages/widgets/Source/Viewer/Viewer.js:429` — `Viewer(container, options)` builds widget DOM and passes options into `new CesiumWidget(...)` (around the `new CesiumWidget` call).
2. Canvas and Scene: `packages/engine/Source/Widget/CesiumWidget.js:209` — `CesiumWidget(container, options)` creates/appends an HTMLCanvasElement, configures its size, and constructs `new Scene({ canvas, contextOptions, ... })` (around lines 330–370). It then creates a `Globe(ellipsoid)` by default unless `options.globe` disables it; attaches globe, imagery layers and terrain provider to Scene.
3. Context ownership: `packages/engine/Source/Scene/Scene.js:136` — `Scene(options)` constructs `new Context(canvas, contextOptions)` unless a `SharedContext` is supplied. It creates `FrameState(context, CreditDisplay, JobScheduler)`, compute engine, command lists and Scene state.
4. Backend currently fixed to WebGL: `packages/engine/Source/Renderer/Context.js:44` — `Context(canvas, options)` calls `getWebGLContext(canvas, webglOptions, requestWebgl1)`, stores `_gl`, determines WebGL2, and initializes WebGL capability limits/caches. This is a renderer boundary, but changing it alone is insufficient because the downstream resource and command APIs are WebGL-specific.
5. Frame lifecycle: `Scene.prototype.initializeFrame` at `Scene.js:4431` updates camera/controller state and frame invariants. `Scene.prototype.render` at `Scene.js:4629` updates FrameState and passes, then calls the internal render pipeline when a frame should be rendered.
6. Globe submission: `Globe.prototype.update(frameState)` at `Globe.js:981` delegates visible render work to `this._surface.update(frameState)`.
7. Quadtree selection/submission: `QuadtreePrimitive.prototype.render(frameState)` at `QuadtreePrimitive.js:361` calls tile-provider `beginUpdate`, selects tiles, creates render commands for selected tiles, and calls `endUpdate`.
8. Terrain/imagery GPU command generation: `GlobeSurfaceTileProvider.beginUpdate/endUpdate` at `GlobeSurfaceTileProvider.js:472/506` resets per-frame state and initializes WebGL `RenderState` values. The provider then groups selected tiles by imagery texture count, calls `addDrawCommandsForTile`, and pushes commands into `frameState.commandList`. Tile loading, terrain mesh creation and imagery decoding/reprojection are CPU/worker/resource responsibilities; GPU buffers, vertex arrays, textures, shader programs and draw commands are created/managed through Renderer classes.
9. WebGL command execution: `Context.prototype.draw` at `Context.js:1407` resolves framebuffer/render state/shader/uniforms, then calls `beginDraw` and `continueDraw` which bind WebGL state and issue GL work. `Scene` owns command ordering/pass execution; `Context` owns low-level WebGL command execution.

## CPU / GPU responsibility split

- CPU / worker side: camera and frustum updates; quadtree traversal, visibility/LOD selection, request scheduling; terrain and imagery requests/decoding/reprojection; tile mesh and imagery metadata preparation; command-list construction and sorting; frame-state/uniform derivation.
- GPU side: WebGL context and capability discovery; shader compilation/linking; buffer/vertex-array/texture/framebuffer allocation; render-state setup; clear/draw/compute/pick execution; framebuffer and resource lifetime/caches.
- The Globe tile provider is not a clean CPU-only layer: it currently creates and manages WebGL-specific `Buffer`, `VertexArray`, `Texture`, `DrawCommand`, `RenderState`, and shader resources. A WebGPU Globe path cannot be achieved by simply swapping the `Context` constructor.

## M0.4 implications / constraints

- Keep `Viewer` WebGL behavior and defaults unchanged; backend choice must be fixed during Viewer/CesiumWidget/Scene construction, never hot-switched.
- A minimal WebGPU proof should be an explicitly separate backend path with a narrow capability contract: request adapter/device, configure the existing canvas with `webgpu`, handle unavailable adapter/device and device loss, respond to canvas resize, and demonstrate clear + triangle + depth in an isolated pass.
- Do not claim Globe, terrain or imagery compatibility. The existing Globe/Quadtree provider is coupled to WebGL resource classes and command execution.
- Avoid converting all `Context` APIs or replacing `DrawCommand` in M0. That would be a general renderer port and exceeds milestone scope.
- Shared files requiring a single integration owner for any M0.4 Viewer/Scene backend selection: `Viewer.js`, `CesiumWidget.js`, `Scene.js`, plus any central renderer facade. No parallel worker should edit these concurrently.
