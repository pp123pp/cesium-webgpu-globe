# M6.O5 — 近岸/海底数据基础与水上海色、折射

> 状态：待实施。所属里程碑：M6 全球海洋；完整水下留在 O7。
> 入口：[M6 总任务](../M6.md) · [主计划](../../docs/OCEAN_PLAN.md) · [设计规格](../../docs/superpowers/specs/2026-11-06-m6-global-ocean-design.md)
> 验收：[M6 验收](../../docs/M6_ACCEPTANCE.md) · [状态](../../coordination/M6-STATUS.md) · [AI 交接](../../coordination/M6-AI-START.md)

## 目标与边界

为近岸海水建立可追溯的海岸/海底数据基础，使水上视角的海色、透射和折射正确响应水深。
全球任意海域可显示海洋；近岸精度以数据覆盖和分辨率为限，不能把粗数据渲染成“已知高精度”。
允许附加开放数据、本地数据或用户提供的数据；不把特定付费服务、插件或下载账户设为前提。
本阶段不做完整碎浪、湿沙和水下视角；O6/O7 消费这里的数据与深度结果。

## 前置与执行约束

- [ ] O0 的数据、坐标、垂直基准、缓存和资源契约已冻结，O1 的海洋分类和椭球内通路可用。
- [ ] O3 的不透明场景深度/颜色与水上合成契约已验收，O4 已发布同帧潮位及时间重置语义。
- [ ] 按 [AGENTS](../../AGENTS.md) / [CI](../../docs/CI.md) 选择最小充分检查，复核当前代码再动手。
- [ ] M5 欠项仍保留；只有直接阻碍深度、渲染合成、数据生命周期的项前置处理。

固定海洋分类回答“是否属于海洋及其连通潮间带候选域”；干湿状态回答“当前时刻是否被海水覆盖”。
两者分别存储；动态海水只从海洋连通区域向岸线扩展，孤立内陆洼地、湖泊与河流不属于本阶段。
新增模块和下游接口须与 O0 的 `docs/M6_OCEAN_CONTRACTS.md` 对齐，下列前序/拟新增模块不属于基线既有 API。

## O5-01 — 建立数据契约与有限本地夹具

- [ ] **产出：** 数据元数据契约、可再分发的最小夹具及明确的全球回退模式。
- [ ] 区分海陆/海洋分类、海岸线、陆地 terrain、bathymetry；列清每种数据解决的问题与空白。
- [ ] 每份数据记录来源、版本、许可、覆盖范围、空间分辨率、水平坐标系、垂直基准和无效值。
- [ ] 定义有效、待加载、缺失、失败、过期和基准未知的状态；不得把缺失样本解释为海底高程零。
- [ ] 把水位、陆地和海底高程转换至 O0 的同一基准；转换不可用时明确降低精度/禁用依赖效果。
- [ ] 准备开阔海、缓坡海岸、小岛/海湾及海岸旁孤立洼地的有限夹具；来源与合成部分分别标记。
- [ ] 优先使用可离线、限范围、限层级的确定性夹具；网络真实海岸只用于另列的数据覆盖验证。
- [ ] **检查：** 已知高程/水位得到正确的水深值；基准偏差、无效值、缺块和接缝都有可观察结果。
- [ ] **退出：** 每个样本能回答“从何而来、精度到哪、何时不可用”，默认路径不依赖付费服务。

## O5-02 — 实现可移动局部海岸域及海洋连通性

- [ ] **产出：** 相机附近数据域、稳定采样、当前潮位的连通干湿范围及失效策略。
- [ ] 保持数据地理定位独立于相机中心；局部坐标域移动时按 O0 原点协议更新而不改变地理位置。
- [ ] 根据海洋种子、岸线及地形连通约束确定可受海水影响范围，保留可涨退的潮间带候选域。
- [ ] 以当前潮位与统一基准高程计算干湿和水深；不能仅用 `height < seaLevel` 淹没内陆洼地。
- [ ] 海域拓扑/固定分类变化与潮位引起的干湿变化分别失效；不要每帧重载固定分类数据。
- [ ] 处理海岸瓦片边界、跨经线、局部域重定位、数据 LOD 替换和迟到请求；避免旧数据覆盖新域。
- [ ] 对加载、解码、GPU 上传、缓存淘汰设定有依据的边界；销毁/关闭后不得继续写入已释放资源。
- [ ] 无覆盖时保留开阔海及远景卫星海色，削弱或关闭依赖精确海底的近岸效果并暴露数据状态。
- [ ] **检查：** 岛屿不被覆盖、海湾可连通、孤立洼地不进海水；同潮位重载数据结果一致。
- [ ] **退出：** 全球可用性与局部精度分开表达，数据缺失不会生成伪海底或伪精细岸线。

## O5-03 — 让海底数据进入生产几何、颜色与深度

- [ ] **产出：** 有效 bathymetry 驱动的实际海底渲染，以及供水面前颜色/深度读取的生产通路。
- [ ] 检查当前 terrain Provider 是否能把海底样本送入既有瓦片/网格。能复用则沿用；不足时按合同新增受海洋范围约束的局部海底网格，记录选择、所有权和替换零高程盖板的规则。
- [ ] 保留陆地、岛屿和海岸接缝，处理海底 LOD、相机域移动、裁剪、背面和资源释放；不创建另一套通用 terrain 引擎。
- [ ] 给有效海底提供明确标注的简化材质及正确颜色/深度；不要求虚构真实海底纹理。缺失或不可信数据不得被默认为真实平底海床。
- [ ] 把实际海底写入水面之前的不透明生产目标，确保海面不会读写同一附件，并沿用地球实体遮挡。
- [ ] **检查：** 用已知样本核对几何高度、水面前深度和遮挡；验证现有零高程盖板不再盖住有效海床。证据必须经过生产绘制路径，不能仅展示独立诊断平面。
- [ ] **退出：** 后续折射及 O7 水下可直接消费海底几何/颜色/深度；数据采样接口或去盖板本身不能算完成。

## O5-04 — 水上视角的透射、海色与折射

- [ ] **产出：** 使用真实场景不透明颜色/深度的水上光学合成及清楚的回退条件。
- [ ] 从 O3 约定的水面之前场景缓冲读取颜色与深度；禁止对正在写入的同一附件采样。
- [ ] 遵守 `WebGPUDepth.js` 的实际深度约定，恢复水面后方可见距离；不能把深度差直接当世界距离。
- [ ] 使用统一基准的水深、视线中的水路径长度及可调水体参数控制吸收/散射和海色。
- [ ] 以波面法线近似折射；限制屏幕边缘、遮挡边缘、无深度和反向命中的采样，避免天空漏进海底。
- [ ] 深水、未知海底和有效浅水分别选择可说明的光学路径；不强求数据空白区域出现可见海底。
- [ ] 处理岸线接触、地形遮挡和近远海色渐变；远景继续使用既有卫星海色，并避免双重海色着色。
- [ ] 与太阳、天空/云近似反射一起合成并保持 HDR/色调映射顺序；SSR 仍为后续可选扩展。
- [ ] **检查：** 有限夹具中浅/深水趋势、被遮挡物、无有效深度、屏幕边缘及相机掠水视角正常。
- [ ] **检查：** 一条已知 bathymetry → 实际海底几何 → 水面前颜色/深度 → 水上折射链路在生产路径上成立。
- [ ] **退出：** 水上折射有真实深度依据，能明确区别数据精度与美术参数，不产生地形穿透或自采样。

## O5-05 — 验证数据替换、回退与 O6 交接

- [ ] **产出：** 数据状态演示、加载失败/切换证据、O6/O7 可消费的近岸与光学输入说明。
- [ ] 记录有效高程/水深、海洋连通性、当前干湿、数据分辨率和有效范围的诊断视图。
- [ ] 对一次正常加载、缺块、失败、数据替换和相机远距离跳转合并验证；拒绝过期请求写回。
- [ ] 在同一潮位下比较细/粗/无数据路径，标出接受的渐入和精度差异，不把回退结果列为高精度通过。
- [ ] 运行聚焦数据检查及一组小规模生产 WebGPU 折射夹具；共享代码变化补实际需要的 WebGL smoke。
- [ ] **检查：** 真实 GPU 型号、源码/bundle、数据来源/版本、参数、限制和执行结果都可追溯。
- [ ] **退出：** O6 可取得可靠的局部水深/坡度/海洋连通域，O7 可取得有效的海底深度与光学参数。

## 最小充分验收

| 风险 | 必要证据 |
| --- | --- |
| 基准或无效样本误解 | 已知 datum 转换、缺值和水深符号的聚焦数值检查 |
| 错淹内陆/瓦片断裂 | 海湾、小岛、孤立洼地、接缝和潮间带的诊断结果 |
| 海底没有真正进入绘制/折射遮挡错误 | 已知 bathymetry 到生产海底几何、颜色/深度和折射的有限硬件夹具 |
| 数据生命周期 | 失败/替换/过期响应/关闭释放的聚焦检查 |

正式海岸性能验收留 O6；这里记录数据/资源边界，不以无依据固定数值承诺全球精度或帧率。
遵守 [CI](../../docs/CI.md)：禁止 SwiftShader，硬件不可用记 blocked/unverified，Full 不自动运行。
数据提供者缺失与实现缺陷分别记录；不得删除有效断言来让回退通过。

## 风险与回退

- 全球粗海底与细地形可能无法一致拼接：保留覆盖/精度状态，岸边效果只在可信范围生效。
- 地形高程不含海底或基准不明：继续开放海渲染，暂停依赖精确浅水的验收，不造假深度。
- 屏幕空间折射只覆盖已渲染可见内容：使用有界回退；需要场景外内容时另列后续改进。
- 潮位改变有效水深：O6 的传播场必须考虑失效，不能长期套用某个静态潮位的预烘结果。
