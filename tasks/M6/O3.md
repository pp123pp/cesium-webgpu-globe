# M6.O3 — 任意海域、跨尺度连续与首次验收

- [ ] **阶段状态：未开始。** 本阶段是海洋首次完整效果/性能决策点，不是 M6 全部验收结束。

## 目标

把 O2 的目标近景效果推广到全球任意有效海域，让用户使用同一 Cesium 相机从近水面自由飞到远景，并跨海域移动。
证明地理重定位、分层曲面、波相位、海洋掩膜、卫星海色和现有天空/云/HDR 在这条路径上连续工作。

## 前置

- [O1](O1.md) 的基础功能和 [O2](O2.md) 的目标近景具备可复用证据；明确仍未通过的项。
- 读取[总任务](../M6.md)、[设计](../../docs/superpowers/specs/2026-11-06-m6-global-ocean-design.md)、[验收](../../docs/M6_ACCEPTANCE.md)与[CI](../../docs/CI.md)。
- 读取 [M6-STATUS](../../coordination/M6-STATUS.md)，只处理直接影响本阶段验收的 M5 未完项。
- 先读 O0 产出的 `docs/M6_OCEAN_CONTRACTS.md`；复用已冻结的接口和数据来源；下列“前阶段建立”文件必须在实际检出中核实后修改。

## 明确范围

- 全球海洋位置可作为输入；不是若干预设小岛之间跳转的局部演示。
- 近水面、低空、中远距及轨道级视图采用同一相机，保留高空卫星海色与现有天体/体积云表现。
- 本阶段首次验收质量、连续性和性能；O6、O7 在后续功能加入后分别复验，不复用 O3 代替它们。
- 先保持目标效果再分析成本；不得未报告就删泡沫、降波场级数或替换天空来满足指标。
- 全面近岸、水下及 SSR 增强不在本阶段；数据分辨率不足的岸线限制如实展示。

## O3-01 — 全球移动与坐标边界连续性

- [ ] **产出：** 全球坐标和局部波场映射在跨纬度、日期变更线、极区及瞬移时稳定的证据。

**步骤**

1. 固定覆盖太平洋、大西洋、印度洋、北冰洋和南大洋的海洋样本；另含日期变更线两侧、极区、海峡和小岛附近。
2. 加入从基本海洋分类中按固定种子选取的额外位置，验证定位入口不依赖预设名单；记录分类源和样本覆盖。
3. 在同一活动相机连续移动中触发局部框架重定位，检视曲面高度、波峰相位、法线、纹理方向与环境切换。
4. 修复经度 wrap、极区局部基向量翻转和相机附近浮点误差；使用稳定地理相位合同，避免每次重定位重置随机种子。
5. 对跨大洋瞬移重建有限资源与历史；对可连续运输的局部变化保持波场，无法复用的泡沫按既定规则渐入。

**针对的检查：** 经纬度边界数值检查、同地同时间基础波场一致性、局部硬件移动片段；不要求历史泡沫随机访问逐像素一致。

**完成条件：** 非预设有效海域也可进入；跨边界无方向翻转、可见相位跳变或大片缺水；覆盖限制与未知区域清楚标注。

**下一步：** O3-02 检查从这些海域向高空飞行的表现连续性。

## O3-02 — 近景到卫星远景的连续过渡

- [ ] **产出：** 一套遵循设计合同的曲面/频带/法线/海色过渡规则和双向飞行证据。

**步骤**

1. 按 O0/O1 合同中记录的视距/屏幕误差规则安排近中远层覆盖，校验实际投影曲率、地平线和网格接缝。
2. 连续衰减无法被像素分辨的位移与高频法线，并匹配 mip/粗糙度；不得通过突然关闭一整级海浪制造跳变。
3. 从当前影像通路读取远景海色，连续混合海洋材质与卫星外观；明确影像缺失时沿用的既有回退。
4. 保证近远重叠区仅有一个有效表面/深度结果，无双层高光、z-fighting、海色硬环或露底缝隙。
5. 以同一路线从近水面升至轨道级再下降，覆盖太阳高光方向、云影/反射、夜间和低太阳场景。

**针对的检查：** 持续运动的相邻帧/固定高度对照、海面边界和地平线检查；不得只在端点截图判断连续性。

**完成条件：** 用户无需换相机/示例即可完成全程；远景仍可识别卫星海色，近景浪形与泡沫保持目标效果；无明显阈值跳变。

**下一步：** O3-03 对快速导航和资源更新压力验证同一过渡路径。

## O3-03 — 快速导航、缺失数据与有限资源

- [ ] **产出：** 自由探索时的更新/失效/回退策略，具有可观察的预算和可恢复错误行为。

**步骤**

1. 快速平移、急升降和跨大洋瞬移，检查掩膜、网格、环境纹理、FFT 与泡沫之间的数据版本一致性。
2. 对晚到资源加代次/有效区域检查；旧海域请求返回不能覆盖新海域，也不能重新点亮已销毁场景。
3. 模拟缺失分类瓦片和影像、临时失败及重复启停，确认未知仍采用保守显示而非错误铺水。
4. 检查缓存逐出、纹理/缓冲上限、resize 和销毁；长距移动不能为每个访问过的海域永久保留一套 GPU 资源。
5. 在示例中保留自由相机控制和可恢复参数重置；固定路线仅作为证据工具，不限制用户探索范围。

**针对的检查：** 小型可重复异步/资源状态用例与一条硬件导航序列，记录帧异常、资源峰值及失败后的恢复状态。

**完成条件：** 无请求回流污染、重复资源增长和未处理 GPU 错误；缺失数据不会制造假海岸或把内陆水体变成海洋。

**下一步：** 稳定后执行 O3-04 一次合并验收；失败先重跑受影响项，避免反复完整矩阵。

## O3-04 — 首次视觉、连续性与性能验收

- [ ] **产出：** O3 验收包与明确的继续/阻塞结论；测试源码、截图和性能数据可追溯。

**步骤**

1. 开始采集前锁定 `docs/M6_ACCEPTANCE.md` 的 O3 设备、预算、场景、分辨率、海况、相机路线、时间/曝光、预热和采样窗口。
2. 在实际桌面物理 WebGPU 上采集目标近景、全球代表海域、近远双向路线和必要的 120 帧运动证据；记录设备/浏览器/适配器。
3. 同一条件比较海洋开/关，分别记录 FFT、泡沫、环境更新、海洋绘制和原天空/云/HDR 的成本。
4. 报告 CPU 帧时、可测 GPU pass 时间、平均值/中位数/p95、帧异常及资源估算/峰值；区分初始化与稳定阶段，显存估算不冒充驱动实测驻留显存。
5. 对照预先锁定的质量/性能判据逐项结论；需要取舍时给出效果损失与成本变化，保留未通过项和明确后续任务。

**针对的检查：** 使用 `M0_GPU_MODE=hardware M0_REQUIRE_PHYSICAL_GPU=1` 的既有浏览器约束；无硬件则阻塞渲染验收。

**完成条件：** 目标外观、地理/尺度连续性和性能有同版本证据；不能用 hosted Fast/Full 绿色替代渲染验收，不能把采样覆盖声称为逐海域穷举。

**下一步：** 无阻塞则进入 [O4](O4.md)；O6 与 O7 按各自新增行为重新验收性能。保留 M5 未完项的真实状态。

## 验证纪律

- 纯文档修订只做内容/diff 检查；实现按真实变更选择最小充分验证，不为完成阶段自动运行所有测试。
- 同一源码/配置/依赖/环境仍适用的证据可复用；必须标出原测试 revision，不描述成当前 HEAD 新跑通过。
- 全局视觉矩阵只在本阶段明确验收时执行，不进入每次 CI 或每个小任务。
- 不使用 SwiftShader；没有物理 GPU 时列明未验证范围，不用软件模拟结果凑齐证据。
- 不手动执行、dispatch 或 rerun Full，也不为触发 Full 改 PR 状态/标签，除非有明确用户授权。
- WebGL 是保留项；共享入口变更的回归风险按现有政策验证，完整 WebGL 差分须单独授权，未执行就明确记录。

## 风险与不做

- 全球可定位不等于岸线/水深在所有位置都精细；基础数据分辨率、缺失状态和极区限制必须显示在证据中。
- 近远混合不能掩盖 O1 未解决的盖板、表面分类或深度错误；发现这些错误应回到对应责任任务修复。
- FFT 统计正确不代表视觉连续；稳定截图漂亮也不代表飞行过程中没有接缝和闪烁。
- 本阶段不引入真实天气/潮汐预报、船只尾流、完整水下或依赖 SSR 的反射。
- 不作绝对工期承诺或未指定硬件的通用 FPS 保证；O3 通过不宣称 M5、M6 后续阶段已完成。
