# M6.O2 — 目标近景：FFT、海色、泡沫与环境反射

- [ ] **阶段状态：未开始。** 实现和验证结果须由后续执行者逐项补充，当前没有任何运行时通过声明。

## 目标

在 O1 的真实全球海洋底座上形成可用于近距离观察的目标效果：多尺度波形、海色、白沫、天空/云倒影和独立太阳高光。
参考 Tidewater 的海洋表现和算法结构，适配现有 CesiumWebGPU 的椭球、单相机、时间、HDR 与资源生命周期。

## 前置

- [O1](O1.md) 的掩膜、负波谷、独立表面类型、颜色/深度和最小出入水通路已具备证据。
- 读取[设计](../../docs/superpowers/specs/2026-11-06-m6-global-ocean-design.md)、[总方案](../../docs/OCEAN_PLAN.md)、[验收](../../docs/M6_ACCEPTANCE.md)与[状态](../../coordination/M6-STATUS.md)。
- Tidewater 固定提交：`4811ba48d795197de5621985f404e765c0b7c0ef`。直接复用代码/资产须有 O0 已核实的许可；来源不明时不能假定可复制。
- 先读 O0 产出的 `docs/M6_OCEAN_CONTRACTS.md`。所有新增接口按该合同落地；本文件中的 `WebGPUOcean*` 为计划模块，不是基线已有 API。

## 明确范围

- 首个高质量 FFT 配置为四级 256；参考长度 `733 / 157 / 33.3 / 7.1 m` 作为初始比较基线，调整要记录理由和视觉影响。
- 海况由人工参数/预设驱动，不接入真实天气，不实现船只、角色、尾流或物体交互。
- 主反射来自现有天空/体积云的方向辐亮度；太阳高光独立计算，SSR 为后续可选增强。
- 海面仍由 O1 的全球海洋分类裁切，远景卫星海色通路保留，跨尺度完整验收在 O3。
- 本阶段泡沫以开阔海浪白沫为主；近岸破浪/回流和完整水下留到各自后续阶段。

## O2-01 — 多级 FFT 与位移/导数输出

- [ ] **产出：** 原生 WebGPU 多级频谱及 IFFT，向 O1 曲面提供位移、法线所需导数和压缩指标。

**步骤**

1. 对照 Tidewater `src/ocean/OceanFFT.js` 的谱演化、行/列 IFFT、频带切分与纹理布局，先固定单位和随机种子。
2. 在现有设备/编码器生命周期内构建四级 256 计算通路；检查设备限制与格式能力，不创建另一个 GPU 引擎。
3. 用 Cesium 帧时间直接驱动解析谱相位，处理长时间精度；局部坐标重定位只改变采样变换，不随机重播波浪。
4. 输出带明确有效版本的位移/导数纹理，正确生成所需 mip 并管理写后读顺序；世界 Y 轴位移转换为局部椭球框架。
5. 对资源不足或不支持的设备清楚报告配置和原因；不得静默降低已约定的目标效果来获得通过。

**针对的检查：** 小规模 CPU 参考 DFT/已知正弦与 GPU 结果比较、频带范围/有限数值、固定种子复现和暂停一致性；容差写入验收记录。

**完成条件：** 各级位移/导数正确、无谱频带明显重复能量或方向颠倒；同一地理点/时间的基础波场不依赖相机行进历史。

**下一步：** O2-02 用生产波场着色；O2-04 消费压缩指标建立泡沫历史。

## O2-02 — 近景海色、法线与光学混合

- [ ] **产出：** 输出场景线性辐亮度的海洋材质，具备多尺度法线、海色、粗糙度和 Fresnel。

**步骤**

1. 复用 FFT 导数构造正确局部法线，结合位移和采样 footprint 处理细波远处闪烁，保持几何/着色方向一致。
2. 建立可解释的吸收/散射或其有界近似，区分有效水深、未知水深与开阔深海；未知水深不能读取虚构海底。
3. 将透射/体色、环境反射、太阳高光与泡沫混合限制在能量和颜色合同内，输出到 O1 的海洋表面分支。
4. 在相同曝光、太阳/云状态下保存近水面与俯视对照，检视蓝绿海色、浪峰/浪谷和掠射角反射。

**针对的检查：** 材质硬件夹具覆盖法线方向、掠射角、曝光变化、低太阳及夜间；检查有限值、异常负色和重复显示转换。

**完成条件：** 海面有深度感且不呈塑料镜面或统一发光色；不以离开 Cesium 的独立天空/色调映射来复制参考效果。

**下一步：** O2-03 替换诊断环境输入为现有天空/云的方向辐亮度。

## O2-03 — 天空/云方向反射与独立太阳高光

- [ ] **产出：** 与当前场景天气外观和太阳状态一致的环境反射输入，具有受控更新成本和有效性。

**步骤**

1. 从现有大气/云算法提取最小可复用方向求值或生成方向纹理；使用当前海面附近空间状态，不新增第二活动相机。
2. 明确海面反射方向、椭球局部地平线和云的采样原点；方向环境须随相关位置、时间、太阳和云设置更新。
3. 环境输入排除独立太阳圆盘重复能量；用现有太阳方向、照明强度和遮挡/透射约定计算一次海面太阳高光。
4. 给粗糙度匹配的环境采样定义滤波与更新节奏；设置变更、瞬移和资源晚到不能继续冒用旧区域环境。
5. 检查日出/日落、夜间、云层开/关及太阳被遮挡时的反射；屏幕外天空和云仍可贡献反射。

**针对的检查：** 同一相机/时钟的天空与海面配对图、太阳高光能量/方向检查、环境失效更新与销毁检查。

**完成条件：** 主反射不依赖 SSR、画面内天空像素或硬编码假天空；太阳高光不与环境圆盘重复；原有天空/云质量保持。

**下一步：** O2-04 完成白沫；SSR 如需添加须另列后续任务，不能成为当前主路径依赖。

## O2-04 — 开阔海白沫与有界历史重建

- [ ] **产出：** 基于波面压缩的动态泡沫，时间和地理失效规则可解释、可复现。

**步骤**

1. 参考 Tidewater `src/ocean/OceanFFT.js` 的 Jacobian 白沫生成和 stateful foam，限定状态资源及衰减规则。
2. 按 O1 时间合同推进连续历史；暂停保持，正常倍速采用受限子步，禁止无限追赶落后的时间。
3. 时间跳转/倒播、海况改变或无法映射的重定位触发有界清理/重建并渐入；基础波场仍直接匹配目标时间。
4. 保持泡沫在海洋分类内，抑制重复周期纹理和硬阈值闪跳；位置有效的历史按合同搬移，不将旧海域泡沫拖到新位置。
5. 为状态恢复提供诊断标记和可配置上限，明确历史泡沫不保证任意随机访问时的逐像素完全一致。

**针对的检查：** 固定路径上的暂停/倍速/倒播/大跳转、相机瞬移和海况切换；断言重建成本上界、有限值和渐入完成。

**完成条件：** 跳转不卡死，泡沫不永久保留、不瞬时铺满海面；可见重建有记录，未宣称真实历史水动力可逆。

**下一步：** O2-05 形成目标近景证据；近岸泡沫/湿润历史沿同一失效合同在后续阶段接入。

## O2-05 — 近景质量收敛与阶段交接

- [ ] **产出：** 受控海况预设、近景效果证据和 O3 需要的资源/计时观测入口。

**步骤**

1. 在现有海洋示例中配置平静、普通风浪和较强海况，保存参数、固定种子、相机、时间与曝光。
2. 对照固定 Tidewater 参考记录已吸收的视觉特点和适配差异，避免宣称两套引擎逐像素等价。
3. 合并相关修改后执行最小数值检查和近景硬件检查；复用仍有效的 O1 深度/分类证据。
4. 记录 FFT、环境更新、海洋绘制、泡沫的独立可观测成本与纹理/缓冲预算，为 O3 统一性能验收提供入口。

**针对的检查：** 近景关键图及短运动片段、GPU 验证错误、资源计数和实际物理适配器；此处不运行全球完整矩阵。

**完成条件：** 目标近景各组成效果齐备且未破坏 O1 合同；剩余外观差异和性能风险逐条列出，未执行项不标通过。

**下一步：** 进入 [O3](O3.md) 的全球移动、跨尺度连续与首次效果/性能验收。

## 风险与不做

- 参考项目的本地世界坐标、计时器、天空引擎和网格不能直接移植为全球方案。
- 四级频带和 mip 处理会影响能量、波形和闪烁；不能仅用静态漂亮截图替代运动检查。
- 不预做海岸精细破浪、船只尾流、真实天气、SSR 必需链路或完整水下。
- 效果优先不代表成本不记录；正式性能决策点为 O3/O6/O7，所有结论注明硬件和场景。
- 无物理 GPU 则记录硬件验收阻塞；不使用 SwiftShader，不自动 Full。
