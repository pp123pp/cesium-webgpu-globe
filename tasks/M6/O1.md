# M6.O1 — 全球海洋底座、时间与真实深度通路

- [ ] **阶段状态：未开始。** 以下均为未来实施工作；不得依据本任务文件宣称代码或渲染已通过。

## 目标

在现有 CesiumWebGPU 内建立可定位全球海域的海洋底座，使同一相机、Cesium 时间、掩膜、表面类型和深度共同工作。
先证明波谷能在平均海面以下正确显示，海陆遮挡与最小出入水通路正确，再叠加 O2 的目标近景效果。

## 前置

- 先读 [AGENTS](../../AGENTS.md)、[M6 状态](../../coordination/M6-STATUS.md)及本任务，确认实际源码 HEAD；无关 M5 未完项继续保留。
- 复用 [O0 历史证据](../../coordination/evidence/M6/O0/README.md)中的仍适用基线。O1-01 的时间/地理 CPU 工作可与 [O0-R](O0-R.md) 并行；**O1-02 依赖 O0-R01—03 的新源与粗细样板数据门槛**，不能只凭旧 NE 证据开始生产覆盖验收。
- 数据路线以 [OCEAN_PLAN](../../docs/OCEAN_PLAN.md) v2.0 为准；需要字段时按标题读取 [接口合同](../../docs/M6_OCEAN_CONTRACTS.md)，需要检查时查 [验收](../../docs/M6_ACCEPTANCE.md)与 [CI](../../docs/CI.md)。
- 表中 `WebGPUOcean*` 均为拟新增模块；使用合同中的签名、单位和资源所有权，不视为现有 API。

## 明确范围

本阶段交付生产路径中的精细海陆掩膜、地理框架、时间适配、基础曲面、表面分类、海域盖板处理和深度合成；实际小岛、海峡及粗细掩膜覆盖在本阶段验收，不推迟至 O5。
基础着色和确定性诊断位移足以验收；四级 FFT、正式泡沫与目标海色由 O2 完成。
只验证最小海面穿越、海陆遮挡、负波谷和有限海下视点通路。完整水下吸收、散射、焦散与体验留到 O7。
保留现有天空、太阳、云、HDR 和 WebGL；不建第二渲染器、第二活动相机或平面演示小岛。

## O1-01 — 单时钟与稳定地理框架

- [ ] **产出：** 海洋帧状态适配器，使用同一 `scene.clock`/`frame.time` 与活动相机。

**步骤**

1. 按现行接口合同从 Cesium 帧时间派生波场时间和历史状态，保留潮位输入且默认值为 0；禁止 `Date.now`、独立播放时钟或仅凭帧数累计海况。
2. 将地理定位、WGS84 法线、局部米制坐标和 GPU 相对坐标分离；保留波场相位的稳定地理锚点。
3. 为暂停、倍速、倒播、显式时间跳转和相机瞬移输出明确的历史有效性；限制历史重建步数和最大步长。
4. 冻结参考海面高、潮位和位移的米制合成与高程基准；不得把椭球高 0 宣称为真实平均海平面，展示型潮汐曲线在 O4 实现。

**针对的检查：** 聚焦单元案例验证同一时间/海况可复现、暂停不推进、跳转有界、长时间数值有限、重定位保持可见波相位。

**完成条件：** 海洋、太阳、天空和云使用相同帧时间；框架变化不会重置海面为随机新相位；不引入新的计时来源。

**下一步：** O1-02 消费地理框架；O2-01 消费波场时间；O2-04 消费历史有效性。

## O1-02 — 精细海陆掩膜与分层曲面覆盖

- [ ] **产出：** 由固定 OSM 快照实际生成的分类资产及生产海面裁切，覆盖已交付的粗细层级，具有有限网格和掩膜资源预算。

**步骤**

1. 消费 O0-R 冻结的活动清单与真实样板，按生产范围生成并登记实际分类资产。保留 `0 unknown / 1 ocean / 2 land / 3 inland-water`；处理里海例外及已核验的湖泊信息，不以 waterMask、负高程或缺失值单独判断海洋。
2. 从同一未简化源生成保守父级与沿岸稀疏细级，纯陆/纯海可用经完整足迹验证的常量；不全球密集生成最高层。完整 texel 足迹须检测内部小岛及边界，混合/未决为 unknown；分类 nearest 采样，不用平均 mipmap。
3. 按相机范围和合同选择自定义 coverage L0—L9，记录实际可用层级；L8/L9 的约 19.1/9.6 m 赤道间距是采样目标，不是 OSM 定位精度，也不是 Cesium terrain z。细级未到只回退到同源兼容且真实有效的数据/父级，否则保留地形/影像并停止该处海洋绘制；不能用漏岛的 NE ocean 补缺。
4. 围绕活动相机构造分层曲面网格并按海洋身份裁切；基础地形调度仍由 Globe 提供。请求、解码、GPU 上传和缓存有界，资产/区域切换以 generation 拒绝迟到写入；静态分类不冒充当前潮位湿区。
5. 消费实际资产复查 Alcatraz、金门/窄海峡、复杂群岛或港口、里海、湖泊/负高程陆地、日期线/极区和缺块恢复；记录源误差、边界 unknown 带、实际细级范围及限制，无需为每处保留独立网格集合。

**针对的检查：** 复用 O0-R 仍适用的数据证据，增加最少的覆盖/层级/回退状态与资源检查；局部物理 GPU 夹具必须读取真实生成瓦片并确认小岛、陆地与内陆水体不被海面覆盖。人工边界可隔离 shader，但不能替代真实资产裁切。

**完成条件：** M6-A02 的精细静态覆盖在交付范围内有生产路径证据，M6-A03 的地理输入不受经度断点限制；未知区域不伪造为海洋，层级切换不重新盖住已识别的小岛，资源受预算约束。未生成范围与源偏差单独记录，样板通过不等于本项通过。

**下一步：** O1-03 在真实生产深度路径中解决海域盖板和波谷。

## O1-03 — 海域零高程盖板、负波谷与遮挡

- [ ] **产出：** 海洋与地形正确共存的深度路径，以及平均海面以下波谷的硬件证据。

**步骤**

1. 复现现有海域零高程不透明盖板遮住负波谷的风险；记录其来自地形、影像还是合成假设。
2. 仅在确认海洋且识别为无有效水深的海域盖板区域排除盖板颜色/深度；保留真实陆地、岛屿和有效海底几何。
3. 让实际位移海面写入现有反向深度约定；不通过把所有浪抬到零以上或修改全局 near/far 遮掩问题。
4. 用受控负位移驱动生产海面网格和着色器，检查波谷、陆地前景、太阳和云的相对遮挡。
5. 覆盖 WGS84 内部被当作实心地球的相关分支；对已分类海域的近海面视点使用有效水面/地形深度，不全局取消陆地遮挡。

**针对的检查：** `m6-ocean-foundation-smoke.mjs` 中真实深度/颜色断言，使用本地有限瓦片夹具；禁止以模拟像素替代生产 shader。

**完成条件：** 正/负位移均可见且无双层 z-fighting；岛屿仍遮挡海面；海下最小视点不会因实心椭球错误全黑或看到地球背面。

**下一步：** O1-04 完成海洋与地形的不同着色语义；后续有效水深接入不需撤销当前盖板合同。

## O1-04 — 独立表面类型与线性 HDR 合成

- [ ] **产出：** 明确区分地形反照率与海洋已着色辐亮度的显式表面类型通路。

**步骤**

1. 依设计文档增加独立表面类型表达并与深度有效像素对应；覆盖清屏、缩放、附件重建和禁用海洋状态。
2. 修改大气开启/关闭及 HDR 对应分支：地形维持原有 Lambert/地形月光行为，海洋不再被重复乘地形光照。
3. 保持海洋辐亮度在线性空间，统一应用视线大气透射和散射，然后进入现有 HDR/Bloom/最终显示转换。
4. 排除重复太阳/环境能量与海洋重复月光加项；以明确诊断颜色验证各表面分支及天空背景。

**针对的检查：** 聚焦分类合成与颜色合同；硬件夹具比较海洋开/关、地形前景、白天/夜间和大气开/关的关键像素/区域。

**完成条件：** 地形既有着色含义保持；海洋无二次 Lambert 或双重 tone mapping；背景未被误标为海洋。

**下一步：** O2 可输出正式海洋线性辐亮度；共享合成入口改动由集成负责人串行合并。

## O1-05 — 最小出入水、开关与生命周期

- [ ] **产出：** 可供后续阶段稳定使用的示例入口、最小海面穿越和可复现检查结果。

**步骤**

1. 在 `Apps/WebGPUOcean.html` 使用现有 CesiumWebGPU Viewer、同一相机和时钟，显示海域/时间/表面类型诊断。
2. 对相机缓慢穿过测试海面验证进入/离开状态、实际遮挡和重新浮出；陆地下穿规则保持受限。
3. 检查启用/禁用、resize、销毁、异步资源晚到及设备丢失处理；不可恢复时清晰报错，不能泄漏或静默换后端。
4. 合并本阶段相关修改后运行最小聚焦检查；记录具体源码、夹具预算、浏览器和物理 GPU。

**针对的检查：** 一次合并的基础单元检查及必要局部硬件 smoke；按变更影响复用适用的既有深度/生命周期/WebGL 证据。

**完成条件：** O1 必需用例通过或逐项有明确阻塞；海洋关闭后既有行为可用；未冒充完整水下质量验收。

**下一步：** 进入 [O2](O2.md)；O7 保留完整水下工作。无物理 GPU 时记录阻塞，禁止 SwiftShader。

## 风险与不做

- 零高程盖板不等于真实海底；不能删除整块地形瓦片来解决海陆交界。
- 源岸线误差与 runtime 采样间距分别公开，不承诺统一米级定位精度；O1 的精细静态覆盖不能等 O5 再补，OSM 静态 MHWS 岸线也不能替代 O5/O6 的动态湿区。
- 海面穿越验证不提前实现焦散、潜水体验、游泳或船只交互。
- 本阶段不导入 Tidewater 引擎、天空、相机和完整 RenderGraph，不改变 WebGL 默认路径。
- 不自动运行/dispatch/rerun Full，不切换 PR 状态或标签专门触发 Full；遵循现有 CI 自动规则。
