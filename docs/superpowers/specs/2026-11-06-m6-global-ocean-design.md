### 非目标

M6 不实现通用 RenderGraph、完整 PBR 引擎、全面 Cesium WebGPU API、3D Tiles/BIM、多人/多相机/VR、海洋业务动力学、真实气象、海啸、全球海冰、船舶游戏或水下生态场景。地球影像中的冰区不等于海冰仿真。运行时数据访问默认沿用项目现有可联网模式；离线整包分发不是本次验收要求。不得自动购买服务或要求用户提供新账户才能开始开阔海实施。

## 4. 源码事实与适配责任

Tidewater 的 `src/ocean/OceanFFT.js` 有四级 256×256 FFT、位移/导数、Jacobian 白沫与 mip；`src/core/CDLOD.js` 和 `WaterSurface.js` 使用平面局部坐标。可参考频谱、FFT、带限采样、网格 morph 和水面着色，全球坐标与曲率由本项目适配。

`WaterMaterial.js` 先调用 `skyReflectionRadiance`，再可选叠加实体 SSR，太阳高光独立计算。`Sky.js` 的水面反射使用天空与云 panorama；不能将另一个 `Environment.js` 的场景 cubemap 等同于水面的实际反射路径。

`OceanFFT.js` 的泡沫与 `ShoreSim.js` 的湿润/退浪残留均依赖前态；`ShoreField.js` 和 `ShoreWaves.js` 依赖局部水深、传播场及固定岸型参数。它们需要区域迁移和时间跳转适配。参考版本只有 seaLevel 接口，没有完整潮汐时间模型。

本项目当前 `WebGPUAtmosphereShader.js` 对场景地表颜色施加地形照明；`WebGPUPlanetShader.js` 用椭球限制空气光路；`WebGPUSunShader.js` 用地球遮挡太阳。海面独立材质、波谷与水下视线需要明确新的表面/介质身份。不能全局关闭地球遮挡，也不能把所有海底不足的区域当作已具备真实海底。

源文件与版本链接集中在 [参考依据](#12-参考依据)。以上是源码分析结论，不是本计划已完成的渲染或性能结果。

## 5. 几何、分类与高程

### 5.1 局部曲面与全局可用性

沿用 CPU 双精度、RTC/high-low ECEF 与反向深度的现有策略。相机附近网格按距离细分，将局部采样位置转换到 WGS84 参考曲面，并沿当地向上方向叠加高度。禁止把地球尺度绝对 ECEF 先合成 float32 再做相减。

网格重定位、日期变更线和极区切换需要保留连续的波浪相位或有界过渡。不得让波浪纹理随相机平移粘在屏幕上。全球单一平面不能替代曲面地平线。有效细节距离、morph 范围和渐入时间是 O0/O1 明确记录的实现参数，不在未测量时承诺全球统一数值。

### 5.2 两种边界

1. **海洋归属与连通性**：区分海洋、陆地、内陆水域和未知区域；简单的水/陆 mask 不足以自动证明是海洋。
2. **当前潮位下的干湿边界**：在可连接到海洋的潜在潮间带内，结合地形/水深和当前水位判断。不得只用静态岸线永久裁掉涨潮区域，也不得淹没与海洋不连通的内陆低洼地。

数据按层级加载、缓存和释放。父级或已知有效数据作为加载失败时的基础表现；不能把 unknown 一律当作海洋。窄海峡、小岛、负高程陆地和图层切换均有专门验收。

### 5.3 高度约定

`surfaceHeight = referenceSeaHeight + displayTideHeight + waveDisplacement`，所有项使用米，并明确如何对应现有地形的椭球高。

此处 `waveDisplacement` 指当地 Up 方向的波高分量；FFT 的水平位移另在局部切平面内应用后映射到曲面。查询动态水面时须使用同一位移/坐标合同，不能把三维位移直接加到标量高度。

参考海面与潮位数据的高程基准由 O0 的数据合同记录。不得将椭球高 0 无条件宣称为真实平均海平面。展示型模式可使用明确标注的简化参考面；如与地形在岸边不一致，需要修正或声明数据限制。

若某海域地形实际提供零高程盖板，O1 必须处理盖板对波谷和下潜通路的遮挡。在确认的海洋范围内采用有边界的海域表面策略；陆地、岛屿和地球背面遮挡继续成立。真实海底精度在 O5 进入数据验收，O7 扩展为水下浏览。

O5 还负责把有效 bathymetry 接入实际海底渲染：优先复用真实 terrain 数据/网格入口；若现有 Provider 不支持海底，则建立受海洋范围约束的局部海底网格。具体接点和所有权记录到合同。数据采样不等于已有海底几何，删除零高程盖板也不会自动产生海底。O5 必须交付可被水面前颜色/深度和水上折射消费的海底生产路径，供 O7 直接沿用；未知区域保持明确回退，不凭空补成“真实海底”。

## 6. 时间、海况、潮汐与历史状态

### 6.1 唯一逻辑时间

从现有 `frameState.time` / `JulianDate` 获取场景时间。CPU 侧计算相对 epoch、相位约简或拆分时间，避免把巨大绝对秒数直接上传为 float32。频谱的随机种子与海况配置须可记录、可复现；相同配置下波形按目标场景时刻求值。

暂停时波浪、潮位、漂移、泡沫衰减和近岸湿润动画停止。倍速时波形与潮位对应 Cesium 时间；历史积分使用有限子步或重建策略。负 delta、巨大时间跳跃不能直接送入正向积分器。

### 6.2 时间不连续

| 情况 | 规定行为 |
| --- | --- |
| 普通正向播放 | 目标时间的波形/潮位 + 有预算的历史推进。 |
| 暂停 | 保持可见动画状态；资源加载可完成，但不得通过墙钟继续推进泡沫。 |
| 大幅跳时/倒放/循环回绕 | 立即求目标波形和潮位；使不适用历史失效，以有界初始化/预热重建并渐入。 |
| 过高倍速、超出历史计算预算 | 保持波形/潮位时间正确，历史效果进入同样的重建/近似模式，禁止卡住主线程追赶全部历史。 |
| 跨区域跳转或更换海况 | 显式更换历史 generation，保留基础海面并渐入新细节，不能复用错误区域/海况的历史。 |

历史重建是已接受的近似，不等于任意时刻泡沫严格一致。渐入由场景时间语义驱动；时间暂停时保持当前可见权重。重复来回拖动时间不得形成无界 GPU 资源或无限预热队列。

### 6.3 展示型潮汐

O4 实现可配置正周期、幅度与相位的展示型周期曲线，示例为 `A * sin(2π * (t - epoch) / period + phase)`。默认关闭或幅度为 0；演示可使用幅度 1 米、周期 43200 秒、相位 0 的明确标注预设。这些数值用于展示，不代表任何地点的真实潮位。

水面几何、水深、岸线干湿、泡沫和相机出入水判断使用同一潮位结果。改变水位使近岸传播场失效时，应有受预算约束的更新策略。真实全球潮位、潮流、风暴潮不作为 M6 完成条件。

## 7. 渲染和模块边界

### 7.1 渲染合同

- 水面在场景线性 HDR 阶段提供已着色辐亮度及表面深度；只做一次最终色调映射。
- 大气合成区分 terrain 与 ocean，海面不再乘一遍地形 Lambert 照明。
- 保留折射所需的海面绘制前颜色/深度。不能同时采样同一张仍作为可写附件使用的纹理。
- 天空/云反射复用现有环境模型，可增加相机附近的低分辨率方向缓存；缓存需响应太阳、云、时间和地域变化。
- 太阳高光共享真实场景太阳参数，云阴影与水面照明一致；镜头光晕留在最后的镜头后期。
- 常规 SSR 的实体深度追踪作为可选项，不强制先添加完整 G-buffer、去噪器或通用反射系统。
- O7 前保留水面上下介质和海底深度的通路；完整吸收、散射、Snell 窗、水线、焦散在 O7 实现。

## 9. 性能与验证

从 O1 开始记录同条件基线与增量成本。O3/O6/O7 正式验收时锁定 GPU、浏览器、分辨率、海况、地形/影像和云配置，并记录平均及 p95 帧时间、可用的 GPU pass 时间、加载尖峰和资源计数。分配字节数不能称为驱动实际 resident VRAM；没有 timestamp-query 时注明墙钟测量限制。

硬件未确定时继续完成效果和测量工具；正式性能项标为未验收，不能虚报 PASS。真实硬件不可用时，可以继续 CPU/静态/文档任务，GPU 验收如实 BLOCKED 或 UNVERIFIED，禁止软件渲染代替硬件验收。

新增测试仅覆盖新关键行为和具体风险，优先复用已有框架与场景。普通任务执行最小充分集合；自动 CI 与手动 Full 按原 `docs/CI.md` 执行，不用此计划扩大授权或绕过门槛。文档包本身只需内容、链接、覆盖范围和补丁检查。

## 10. 风险与预先处理

| 风险 | 归属阶段 | 必需处理 |
| --- | --- | --- |
| 影像/地形海域零高程盖板挡住波谷 | O1 | 保留陆地遮挡，明确海洋范围内的深度策略。 |
| 水面被地形照明重复处理 | O1/O2 | 表面类别、线性 HDR 与独立水面材质。 |
| 全球重定位造成波浪相位跳变 | O1/O3 | 可复测移动路径和局部坐标/相位连续策略。 |
| SSR 无法提供所需天空云信息 | O2 | 环境反射为主，SSR 可选。 |
| 时间回拨让历史积分发散 | O1/O4 | 区分绝对求值和历史推进，generation 失效与有界重建。 |
| 潮位与固定海岸传播场不一致 | O4/O6 | 同一高度基准、失效/重建和预算。 |
| 海底数据缺失却宣称真实海底 | O5/O7 | 质量等级、覆盖记录和明确回退。 |
| 最后水下发现椭球遮挡不成立 | O1/O7 | O1 验证最小通路，完整视觉最后交付。 |

## 11. 留给实施者的选择

实施者可根据源码和测量决定网格环数/细分、FFT 精度档位、数据瓦片格式、缓存容量、环境缓存分辨率与更新节奏、渐入阈值及 history 子步预算，并在 O0 合同或对应阶段证据中记录理由。这些选择不能改变已确认的视觉范围、全球可达性、唯一时间来源、展示型潮汐语义和水下最后交付顺序。

未来 API 名称在 O0 冻结；后续如需等价更名，同步所有调用方、任务与文档。不得把实现选择重新包装成用户尚未回答的需求，反复阻塞已授权工作。
