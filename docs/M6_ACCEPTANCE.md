## 3. 证据结构

阶段证据放在 `coordination/evidence/M6/Ox/`，由实际执行任务创建。至少包含：源码及 bundle 版本、命令、环境、检查结果、画面/短录制、性能记录、限制与下一步。原始失败记录不被删除来制造全通过结果。

技术检查 PASS、视觉接受与性能接受分别记录。状态文档中的 ACCEPTED 必须对应所需证据；不能用只读代码检查、CPU 测试或 hosted Fast/Full 成功替代物理 GPU 的目标画面验证。

## 4. 性能口径

1. O1/O2 记录成本，优先完善画质；O3/O6/O7 锁定正式验收设备与预算。
2. GPU 型号/浏览器/分辨率/云与地形设置必须齐全；不同条件不能直接比较增量。
3. GPU timestamp-query 可用时记录相关 pass；不可用时明确 wall-clock、提交等待等测量边界。
4. 稳态记录平均/p95，另记录首次加载、远距离跳转和近岸数据加载尖峰。
5. 纹理/缓冲区分配量与 resident VRAM 是不同指标；未测项明确标注。
6. 未确定目标硬件或未完成测量时，性能项为 UNVERIFIED，不自动填一个 30/60 FPS 结论。

O3 正式测量前记录并锁定 `adapter/vendor/device/driver`、浏览器完整版本、操作系统、viewport/DPR/resolutionScale、源码/dirty diff/bundle/资产哈希、相机路径、UTC 采样序列、seed/seaState/tide/FFT/网格/云/HDR配置、预热与采样帧数、计时方法和预算批准记录。首次候选是已有证据使用过的本地 Intel Xe-LPG，**O0 没有重新探测或指定其为已获批准目标**；执行时记录实际 adapter，不得沿用旧名称代替探测。

冻结的初始协议以 `scenarios.json.performance` 为唯一参数源：同一配置按 off/on/on/off 与 on/off/off/on 两组配对顺序，稳态每块预热20帧、采样120个间隔，累计每模式480个间隔；独立pass计时与自然帧节奏分开，截图/读回放计时窗口外。另采首次加载、连续飞行、跨区跳转和近岸加载的全部帧与最大尖峰，不能删掉慢帧算稳态。帧 CPU/墙钟、GPU timestamp 和 submit-to-completion 分开命名；timestamp-query 不可用时 GPU pass 项为不可测，不以 CPU 时间改名。这个协议用于到 O3 作决定，不是新运行结果；O6/O7 在相同基础上加本阶段路径并重新批准预算。

## 5. 原有测试政策

遵守根 `AGENTS.md` 与 `docs/CI.md`：最小充分验证、适用证据复用、真实 GPU、禁止 SwiftShader。文档变更不跑渲染；普通小任务不反复全套 Full；不自动添加标签或切换 PR 状态触发 Full。必须执行的最终门槛仍须实际完成，并记录其源码与环境。
