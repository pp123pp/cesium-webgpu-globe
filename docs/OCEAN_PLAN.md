## 1. 已确定的方案

- 继续使用现有 Cesium WebGPU，保留地球、地形、天空、太阳、体积云、云影与 HDR，保持 WebGL 原行为。
- 一个主相机，可自由探索全球任意海域；首先交付全球开阔海。
- 近景以 [Tidewater](https://github.com/dgreenheck/tidewater) 为视觉与算法参考。相机附近分层曲面网格配合多尺度 FFT，远景保留现有卫星影像海色，允许细节渐入。
- 反射主体是现有天空/云的方向辐亮度与太阳高光。SSR 可行，但作为后续可选增强。
- 海况人工控制；首期只包含海洋。不实现船舶浮力、尾流、真实天气或业务海洋动力学。
- 潮汐采用可调幅度、周期和相位的**展示型涨落**，预留真实潮位数据接口。
- Cesium 时间轴统一控制场景动画。波形和潮位直接对应目标时间，跳时/倒播后的泡沫及近岸历史允许有界重建、渐入。
- 开阔海之后完善潮汐、近岸和数据；**完整水下最后做**。前期仅验证后续可接入的深度、遮挡、介质和相机通路。
- 桌面端 WebGPU，先目标效果，O3/O6/O7 进行正式性能验收；此前持续记录成本。

## 2. 与当前仓库的关系

计划基于 `8434abc1124fa5389b13f90816d8c2acf52a4382`。M5 不是已经全部完成：已有参考场景、镜头高度和时间连续性成果，剩余运动稳定性、生命周期、性能及最终回归继续跟踪。

用户要求海洋成为下一优先阶段，因此不把“先完成全部 M5 尾项”作为 M6.O0 的通用前置。发现直接阻塞海洋的旧问题时，只处理具体阻塞；其余欠项保留。不得据此宣称 V1.0、M5 或新的 M6 已通过验收。

既有 A01—A18 门槛和 WebGL 策略保留；原 A19（模型/城市）转到 M7，海洋使用独立的 M6-Axx 验收编号。

### 三次完整交付

1. **全球开阔海版：O0—O3。** 全球可到达，近景可展示，高空保留影像，时间统一。
2. **潮汐与近岸版：O4—O6。** 增加可控海平面、岸线/水深及精细近岸效果。
3. **完整水下版：O7。** 最后补齐下潜和水下光学，并完成整体验收。

采用阶段依赖而非未经测量的日历承诺。O1 完成后，依据实际接入难度记录首次工期估算；O3 后重新估算近岸与水下。估算不得改写已确认的阶段顺序。

## 4. 后续 AI 的执行方法

阅读顺序：

1. 根目录 `AGENTS.md`。
2. `coordination/STATUS.md` 的当前优先级和 `coordination/M6-STATUS.md`。
3. `tasks/M6.md` 与当前子阶段文件；首次为 `tasks/M6/O0.md`。
4. 本计划及设计/实施计划中与当前任务相关的部分。

首次明确下一项为 **O0-01**。以后从 M6 状态表选择当前子阶段第一项未完成任务。每次完成一个可审查任务或用户指定的同阶段连续任务，不一次性实现整个 M6，不跳到 M7。

默认继续时，沿用已确认的需求和普通实现判断；不要重复询问引擎、全球范围、是否展示型潮汐、水下顺序或是否允许泡沫重建。确实改变范围的数据许可、效果取舍或不可解决阻塞才向用户提出具体问题。

本计划适用于能够读写仓库的 AI 工具，不要求安装特定插件。并行协作可用时，遵守原项目单一集成负责人、独占文件与最小验证规则。提交、push、PR 和 merge 仍按用户当次授权及原仓库政策执行。

完整可复制提示词在 [M6 AI 执行入口](../coordination/M6-AI-START.md)。

## 5. 验收与状态

每次交接记录：实际源码版本、修改文件、完成的任务、实际运行的检查及结果、截图/视频或测量路径、限制和下一项。不得把计划中的检查写成已执行。

性能记录包括 GPU/浏览器/分辨率、场景配置、GPU pass 时间（若可用）、平均/p95 帧时间、移动/加载尖峰和资源计数。GPU 未选定时先继续效果与测量准备；正式性能门槛到里程碑锁定，未锁定或未测量的项不记 PASS。

文档变化只做内容/链接/diff 检查。运行时变化遵循原最小充分检查、物理 GPU 和 CI 规则；不因交接或提交反复执行全套 Full。
