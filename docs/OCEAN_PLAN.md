# M6 全球海洋技术路线

版本 **2.0** · 2026-11-06 · 按全球海洋与精细岸线需求修订。

**当前默认下一项：O0-R01。** OSM 全球快照尚未取得/审核；分类样板、运行时瓦片、海洋代码和 GPU 验证尚未完成。路线文档完成不等于数据或渲染通过。O1-01 的 CPU 时间/地理框架可独立并行；O1-02 必须等待 O0-R01—03。

## 1. 优先级与历史边界

M6 全球海洋仍是下一开发重点；原 3D Tiles/BIM 阶段顺延至 [M7](../tasks/M7.md)。M5 的镜头/时间连续性成果保留，运动稳定性、生命周期、profiling 和最终回归继续开放。只把直接阻塞当前海洋任务的问题作为前置，不把本次改排当成 M5/V1.0 验收。

原 O0 的 Natural Earth 源、许可、26 个规则样本及接口审计保持历史 `TECHNICAL_PASS`。这证明旧规则可复核，不证明全球岸线准确；恶魔岛漏岛是已知反例。旧 manifest 和 O0 证据不改写为新路线结果。当前文档基线是 `e91ae8c4e9070f5abca3674eee05483c976d5562`；已有接口核查版本与拟新增接口见合同。

## 3. 全球海岸线与分类数据

### 3.1 主源与唯一入口

新的唯一活动入口是 [coverage-manifest.json](../packages/engine/Source/Assets/Textures/WebGPU/Ocean/coverage-manifest.json)：`schemaVersion=2`、`routeVersion=2.0`。当前 `status=SOURCE_NOT_ACQUIRED`，`runtimeAssets.status=NOT_GENERATED`、`files=[]`。未取得输入的时间、字节、SHA256、归档路径以及实际 sourceId/buildId 均为 null。

| 数据 | 已定用途与边界 |
| --- | --- |
| OSM 未简化 WGS84 split **water polygons** | 海域面主源候选；由 coastline 组面，必须审核里海例外与切分拓扑。 |
| OSM 未简化 WGS84 split **land polygons** | 岛屿/陆域边界及海域互校；须与水面包核对快照一致性。 |
| 独立内陆水层 | O0-R01 另行选源/核查覆盖，用于已知内陆水分类；water-polygons 不提供普通湖库全覆盖。 |
| 旧 Natural Earth v5.1.2 | 仅保留原 manifest、许可和 O0 审计输入；不得作为新 runtime 默认或细层失败后的 ocean 回退。 |

官方候选包是 `water-polygons-split-4326.zip` 和 `land-polygons-split-4326.zip`。**split 是切分大面，不是简化岸线。** 不选供低 zoom 使用的 simplified 版本；Mercator 版本裁去约 ±85.1° 之外区域，不作为全球极区底座。候选 URL 的当前可用性、实际批次和文件内容由 O0-R01 核验，不能将 URL 当固定版本。

OSM 数据采用 ODbL，须保留 `© OpenStreetMap contributors` 并核查实际快照及派生数据的分发要求；不能沿用 Natural Earth public-domain 声明。运行时消费项目分发的派生资产，不动态请求 OSM 编辑 API、Overpass 或生产服务进行海陆判定。

### 3.2 分类语义与精度边界

四类保持 `0 unknown / 1 ocean / 2 land / 3 inland-water`。只有经过拓扑和语义核查的 ocean 可以绘制海面；负高程、底图颜色或 terrain waterMask 都不能独立证明海洋归属。

- OSM coastline 表示 **平均大潮高潮线（MHWS）**，不是即时水线或平均海平面高度；南极冰架处还有冰前缘语义。真实潮间带、高程与海底仍归 O5。
- 里海使用 coastline 标签，是明确的内陆例外。将同类切分/重叠合并并保留孔洞后，再验证矢量连通性；用开阔太平洋种子 `(-150°,0°)` 识别世界海洋。其他闭合组件经核查归内陆水，不能确定则 unknown。
- 不照搬旧 Natural Earth 单记录/顺时针外环算法。切分线、重叠边、日期线和极区人工切口不是实际海岸；不得在粗 raster 上 flood-fill 反推海域连通性。
- coastline land-polygons 只先证明非海洋，不能证明面内没有普通湖库。内陆层覆盖/有效性未核验的范围保持 unknown + inland-unresolved；缺层、未加载或无要素都不能直接认证 land=2 或纯陆常量/父级。只有已审核的陆地证据可认证 land；已确认海洋可独立分类，不把未审核内陆范围声称为全球四类验证完成。
- OSM 矢量没有统一“米分辨率”或全球定位误差保证。源几何细节、最终像元采样间距、实际岸线定位精度须分开报告；重采样不能补回源中不存在的岛屿。

### 3.3 已核对的小样本，尚未完成的验证

对 O0 恶魔岛样本 `(-122.421371°,37.826547°)`，原 Natural Earth 分类为 ocean；本次读取官方 [OSM way 295140461/full](https://api.openstreetmap.org/api/0.6/way/295140461/full)，way v16，135 个节点引用（134 个唯一节点），轮廓闭合且逆时针，点入多边形结果为 inside。这个比较证明**原始 OSM 岸线在此点保留了岛屿**。

该小样本不是 osmdata 全球发布包，不证明包内几何、转换器、父子分类瓦片或 GPU 输出已通过。O0-R02 须对同一点和完整岛屿足迹重做粗细层样板；没有取得/归档的全球文件不得填写校验和。原 O0 26 个规则样本通过也不能抵消已记录的地理误分类。

## 4. 数据生成与分级

### 4.1 生成顺序

1. **O0-R01 固定输入。** 取得实际候选包，记录获取时间、源数据时间、字节、SHA256 和许可；核对水/陆快照是否一致。另行决定内陆分类层及覆盖限制，验证里海和其他闭合水体。源缺失或审核失败就停止该次生成，不能发布空包冒充成功。
2. **规范化几何。** 使用真实面与孔洞关系，处理同类重叠/切分和周期边界，记录坐标精度及修复规则。不能用无依据的容差把海峡封死、把小岛抹平或把内陆水接到海洋。
3. **O0-R02 生成小范围样板。** 由同一快照生成粗层、细层及保守父级；对恶魔岛、小于像元的岛屿、狭窄海峡、切分接边、日期线、极点和里海进行有判别力的验证。样板同时核对完整足迹和 unknown 原因。
4. **冻结可用性与回退。** 记录哪些细层存在、哪些区域为已证明常量、哪些像元不确定；细层缺失与边界不确定分别测试。不得用 NE 漏岛结果给新细层作安全父级。
5. **O0-R03 交接，O1-02 接生产。** 冻结实取源、样板结论及输出约定；样板证据不自动等于全球 runtime 资产。O1-02 生成/发布实际可用资产并实现有限调度、加载和 GPU 消费，逐项记录实际文件与哈希。

本次仅交付路线与合同；没有实现新源转换器、下载全球 ZIP 或生成分类瓦片。尚无真实编码样板的可用性/原因索引，在 O0-R02 冻结后再由 O1-02 消费，不提前创建通用 GIS 框架。

### 4.2 自定义 coverage 层级

L0 沿用 8192×4096 全球经纬网和 16×8 个 512² 瓦片，每升一级两个轴各加倍。coverage L0..L9 是本项目自定义层级，**不是 Cesium terrain level，也不是 WebMercator zoom**。

| 层级 | 逻辑全球宽×高 | 赤道东西向采样约值 | 用途 |
| --- | --- | --- | --- |
| L0 | 8192×4096 | 4.89 km | 同源保守底层、全球粗覆盖 |
| L4 | 131072×65536 | 306 m | 按可见需求细化岸线 |
| L6 | 524288×262144 | 76.4 m | 中近岸细节 |
| L8 | 2097152×1048576 | 19.1 m | 精细采样目标 |
| L9 | 4194304×2097152 | 9.6 m | 精细采样目标 |

采样估算用 WGS84 赤道周长除以该层宽度；其他纬度的东西向间距随纬度缩短。表中尺寸是索引范围，不是必须物化的整幅图。L8/L9 不是已交付资产或全球米级定位承诺。只把原 8K 图切成更多文件不会提高空间精度。

**岸线附近稀疏细化，已证明纯海/陆的区域用常量表示；全级合计起始驻留预算为 32 个实际 512² 分类瓦片。** 父级也计入预算；CPU 解码、在途请求和元数据须另设有界预算并实测。不能每级各放 32 个，也不能密集生成全球 L9。

分类 R8 保存离散值，nearest/精确读取，不做线性插值或平均 mipmap。每一像元要求完整足迹属于同一已知类别；边界穿过或整座小岛落在内部时都须保守处理，中心点/四角抽样不足。父级必须来自同一已审快照，保守覆盖全部子足迹。具体坐标、原因字段和回退顺序见[合同的 OceanCoverageSample](M6_OCEAN_CONTRACTS.md#oceancoveragesample拟新增o1-02)。

缺数据时保留同源有效数据，其次使用已发布同源保守父级，最后 unknown 并保留地形/影像；不得退回 NE ocean 或由 unknown 推断可删地形。近岸细层加载前可能暂不绘制该处海面，这是有意的保守表现，不能用漏岛底图把空缺填成海洋。

## 5. 保留的渲染与时间架构

采用共享多尺度 FFT 与主相机附近的分层**曲面网格**，保持 CPU 双精度、RTC/high-low ECEF 和反向深度。coverage 瓦片分级只负责数据精度，不把海面架构改成每个地理数据瓦片一套独立波场/网格。波场锚点与可移动的渲染 RTC 原点分离，跨区域、日期线和极区允许有界细节过渡，基础曲面保持连续。

四级 256 FFT、参考频段长度、位移/导数及 Jacobian 白沫已写在 [O2](../tasks/M6/O2.md)，继续按该任务实施。不能把平面参考坐标、世界 Y 波高或累计墙钟直接移植到地球。水面三维位移与相机介质查询使用同一真实表面；参考海面椭球高 0 只是展示基准，不是全球真实 MSL。

时间从同一 frame.time / JulianDate 派生，波形和潮位绝对求值；暂停保持，跳时/倒播/循环/超预算时使历史失效并有限重建、渐入。展示型潮汐在 O4 实现；默认幅度 0，演示预设明确标注，不能作为真实潮汐预测。具体相位约简、步数、权重和单位只在合同维护。

海面在线性 HDR 中输出已着色辐亮度及真实深度，天空/云反射复用现有场景模型，太阳高光独立且不重复计能量。opaque 与海面读写附件分开；大气按 surface type 区分 terrain/ocean，避免二次 Lambert 和二次显示转换。零高程盖板仅在确认海洋且识别为无有效海底时处理，保留真实陆地/岛屿、有效海底和地球背面遮挡。O1 证明通路，O5 提供真实水深/海底与水上折射，O7 最后完成水下光学。

## 7. 执行与验收

默认先读 `AGENTS.md`、[M6 状态](../coordination/M6-STATUS.md)和当前 `tasks/M6/O0-R.md` 或对应 Ox 文件；再按任务需要查本路线和[合同](M6_OCEAN_CONTRACTS.md)的相关章节。总 STATUS 只在需要核对既有阶段事实时查相应段落。每次推进一个可审查任务；默认下一项由状态维护，不重复询问已经确认的引擎、范围、潮汐语义和水下顺序。

数据验证按原始 API 样本、固定发布包、转换后的矢量、粗细分类样板、生产 GPU 五层区分。比较地理真值、源几何和输出像元；不能只让旧规则样本“仍然通过”。加载失败、迟到请求、跨源切换和缺父级也要验证保守行为。仅记录已执行结果；未取得源、未生成栅格、未运行 GPU 都保持相应未完成状态。

每次交接记录实际版本、改动文件、运行检查、结果和限制。文档改动只需内容/链接/diff 与 JSON 检查；不制造 runtime 测试。运行时采用最小充分检查，物理 GPU 缺失时明确 BLOCKED/UNVERIFIED，禁止 SwiftShader 替代。Full、push、merge 和发布仍按当次授权与既有 CI 规则执行。

O3/O6/O7 锁定 GPU、浏览器、分辨率、地形/影像、海况和云配置，记录平均/p95 帧时间、可用 GPU pass 时间、加载尖峰与资源计数。没有 timestamp-query 时注明测量限制；分配字节不称为实际 resident VRAM；未测项不能记 PASS。具体 M6-Axx 门槛见[验收矩阵](M6_ACCEPTANCE.md)。
